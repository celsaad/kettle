Examples

Libraries you can start from

Four complete programs, each one a single valid file. Copy one into the app and press start today, or open it in an editor and treat it as a worked example of the format. They're plain text either way. Each one writes its weeks out in full, rest days included, so the app schedules them the way the program intends.

Getting one into the app

Copy YAML puts the whole file on your clipboard; in Kettle, open Library → Import → Paste YAML instead, paste, and review. That's the short path on a phone. Download saves the .yaml file instead, for Library → Import → Choose exercises.yaml.

Either way you get the same preview of what's new and what's changing before anything is written, and the same inline error if the file doesn't validate.

Importing adds; it doesn't replace. A library merges into yours keyed by id — new ids are added, existing ones are overwritten, and anything you have that isn't in the file is left alone. Your session history is a separate log and is never touched by an import.

Every id in these four files carries its own prefix (bfb-, ppl-, bw-, cnd-) precisely so none of them can overwrite an exercise you already have. The trade is that you may end up with a second “Push-ups” sitting next to your own — delete whichever you don't want.

Nothing here is meant to be used unedited. The numbers are a starting point; the file is yours the moment it lands, and the app writes your edits back to it in the same format.

Writing your own

The format reference is the full spec — the file shape, the seven exercise types and their config fields, circuits, programs and the merge rule. These four files between them use every type and every structure it documents, so reading one alongside the reference is the fastest way in.

You can also hand the reference to an AI assistant and have it write a program to your own constraints — Kettle itself has no AI features and never calls a model; see using an assistant.
